# 演员信息管理系统设计文档

## 1. 系统概述

演员信息管理系统是媒体库管理系统的核心组件之一，专门负责管理和维护演员相关数据。该系统支持演员信息的爬取、存储、清理和合并等功能，能够从多个数据源获取演员详细信息，并提供智能化的数据清理和去重机制，确保演员数据的准确性和完整性。

## 2. 核心功能

### 2.1 演员信息爬取
- 从JAVDB网站爬取演员基本信息
- 支持批量爬取多个演员数据
- 自动获取演员头像和个人资料
- 提取演员出演作品列表

### 2.2 演员数据管理
- 演员基本信息的存储和更新
- 演员别名和多语言名称管理
- 演员头像的本地存储和管理
- 演员个人资料的完整维护

### 2.3 智能数据清理
- 自动检测重复演员记录
- 基于多种策略的智能合并
- 演员关联关系的自动维护
- 数据一致性检查和修复

### 2.4 批量处理与优化
- 支持批量导入和导出演员数据
- 提供详细的处理进度和统计信息
- 实现高效的批量更新机制
- 支持断点续传和错误恢复

## 3. 系统架构

![系统架构图](系统架构图.png)

系统主要由以下组件构成：

1. **数据爬取模块**：从JAVDB等网站获取演员信息
2. **数据存储模块**：管理演员数据在数据库中的存储
3. **数据处理模块**：负责数据清理、合并和优化
4. **关联管理模块**：维护演员与视频的关联关系
5. **批量处理模块**：控制批量操作流程和进度显示
6. **用户界面模块**：提供用户交互界面和操作反馈

## 5. 数据模型

### 5.1 演员信息模型
系统管理的演员信息包括：
- 基本信息：姓名、外文名、别名
- 个人资料：出生日期、出道日期、身高、三围
- 多媒体资源：头像URL、本地头像路径
- 网络资源：个人资料页面URL

### 5.2 数据库表结构
系统主要与以下数据库表交互：
- `actors`：存储演员基本信息
- `video_actors`：存储视频与演员的关联关系
- `videos`：存储视频信息（通过关联获取演员出演作品）

### 5.3 数据关联关系
- 演员-视频：多对多关系，一个演员可以出演多个视频，一个视频可以有多个演员
- 演员-头像：一对多关系，一个演员可以有多个头像，但通常只使用一个主头像
- 演员-别名：一对多关系，一个演员可以有多个别名

## 8. 使用指南


### 8.2 基本使用

## 13. 附录

### 13.1 常见问题解决
**Q: 演员信息爬取失败怎么办？**
A: 检查网络连接和代理设置，确认目标网站可访问。

**Q: 演员合并错误如何恢复？**
A: 系统会自动备份原始数据，可以从备份恢复。

**Q: 头像下载失败如何处理？**
A: 系统会自动重试，也可以手动下载后更新数据库。

### 13.2 性能指标
- 单个演员爬取时间：5-15秒
- 批量处理速度：约200-300演员/小时
- 内存占用：< 300MB
- 网络带宽需求：< 500KB/s

### 13.3 数据字段说明
- `name`：演员主名称（日文）
- `name_en`：演员英文名
- `profile_url`：个人资料页面URL
- `avatar_url`：头像图片URL
- `local_avatar_path`：本地头像文件路径
- `birth_date`：出生日期
- `debut_date`：出道日期
- `height`：身高
- `measurements`：三围
- `description`：个人描述

### 13.4 数据清理规则
1. **名称相似度**：基于字符串相似度算法，阈值可配置
2. **URL匹配**：完全相同的URL视为同一演员
3. **头像相似度**：基于图像哈希算法，阈值可配置
4. **关联关系**：合并时保留所有关联关系，避免数据丢失
5. **优先级规则**：信息更完整的记录作为主记录
