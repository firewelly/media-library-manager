# 媒体库管理系统数据库详细设计文档

## 1. 数据库概述

媒体库管理系统采用SQLite作为数据存储引擎，具有轻量级、零配置、跨平台等特点，非常适合个人或小型应用使用。数据库设计遵循第三范式，确保数据的完整性和一致性。整个数据库包含8个主要表，用于存储视频文件信息、元数据、演员信息、标签和文件夹结构等数据。

## 2. 数据库文件信息

- **数据库文件名**: `media_library.db`
- **存储位置**: 项目根目录
- **备份目录**: `db_backups/`
- **初始化脚本**: `init_database.py`

## 3. 表结构详细设计

### 3.1 videos表

**功能**: 存储视频文件的基本信息，是整个数据库的核心表。

**表结构**: 
```sql
CREATE TABLE videos (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    file_path TEXT NOT NULL UNIQUE,
    file_name TEXT NOT NULL,
    file_size INTEGER,
    md5_hash TEXT,
    duration INTEGER,
    date_added TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_modified TIMESTAMP,
    folder_id INTEGER,
    FOREIGN KEY (folder_id) REFERENCES folders (id)
);
```

**字段说明**: 
- **id**: 视频唯一标识符，自增主键
- **file_path**: 视频文件的完整路径，唯一约束
- **file_name**: 视频文件名
- **file_size**: 文件大小（字节）
- **md5_hash**: 文件的MD5哈希值，用于文件完整性验证和重复检测
- **duration**: 视频时长（秒）
- **date_added**: 视频添加到数据库的时间戳
- **last_modified**: 文件最后修改时间
- **folder_id**: 所属文件夹ID，外键关联folders表

**索引**: 
- `idx_videos_file_path` (唯一索引，用于快速查找和防止重复)
- `idx_videos_md5_hash` (用于快速重复检测)
- `idx_videos_folder_id` (用于按文件夹查询)

### 3.2 actors表

**功能**: 存储演员信息。

**表结构**: 
```sql
CREATE TABLE actors (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE,
    japanese_name TEXT,
    avatar_url TEXT,
    avatar_path TEXT,
    birth_date TEXT,
    height INTEGER,
    bust INTEGER,
    waist INTEGER,
    hips INTEGER,
    debut_date TEXT,
    description TEXT,
    gender TEXT DEFAULT 'female'
);
```

**字段说明**: 
- **id**: 演员唯一标识符，自增主键
- **name**: 演员姓名，唯一约束
- **japanese_name**: 演员日文原名
- **avatar_url**: 演员头像的网络URL
- **avatar_path**: 本地存储的头像路径
- **birth_date**: 出生日期
- **height**: 身高（厘米）
- **bust**: 胸围（厘米）
- **waist**: 腰围（厘米）
- **hips**: 臀围（厘米）
- **debut_date**: 出道日期
- **description**: 演员简介
- **gender**: 性别，默认为'female'

**索引**: 
- `idx_actors_name` (唯一索引，用于快速查找演员)

### 3.3 video_actors表

**功能**: 视频和演员之间的多对多关联表。

**表结构**: 
```sql
CREATE TABLE video_actors (
    video_id INTEGER,
    actor_id INTEGER,
    PRIMARY KEY (video_id, actor_id),
    FOREIGN KEY (video_id) REFERENCES videos (id) ON DELETE CASCADE,
    FOREIGN KEY (actor_id) REFERENCES actors (id) ON DELETE CASCADE
);
```

**字段说明**: 
- **video_id**: 视频ID，外键关联videos表
- **actor_id**: 演员ID，外键关联actors表
- **复合主键**: 确保一个演员在同一个视频中只出现一次

**关系特性**: 
- 配置了级联删除，当视频或演员记录被删除时，关联记录也会自动删除

### 3.4 javdb_info表

**功能**: 存储从JAVDB网站获取的视频元数据。

**表结构**: 
```sql
CREATE TABLE javdb_info (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    video_id INTEGER UNIQUE,
    title TEXT,
    original_title TEXT,
    release_date TEXT,
    duration INTEGER,
    director TEXT,
    studio TEXT,
    label TEXT,
    series TEXT,
    score REAL,
    cover_url TEXT,
    cover_path TEXT,
    description TEXT,
    magnet_link TEXT,
    FOREIGN KEY (video_id) REFERENCES videos (id) ON DELETE CASCADE
);
```

**字段说明**: 
- **id**: 唯一标识符，自增主键
- **video_id**: 关联的视频ID，唯一约束，确保每个视频只有一条JAVDB信息
- **title**: 视频标题
- **original_title**: 视频原始标题（通常是日文）
- **release_date**: 发行日期
- **duration**: 视频时长
- **director**: 导演
- **studio**: 工作室
- **label**: 发行商
- **series**: 系列
- **score**: 评分（0-10分）
- **cover_url**: 封面图片的网络URL
- **cover_path**: 本地存储的封面路径
- **description**: 视频描述
- **magnet_link**: 磁力链接

**索引**: 
- `idx_javdb_info_video_id` (唯一索引，用于快速查找特定视频的元数据)

### 3.5 tags表

**功能**: 存储系统中的标签信息。

**表结构**: 
```sql
CREATE TABLE tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE,
    category TEXT,
    description TEXT
);
```

**字段说明**: 
- **id**: 标签唯一标识符，自增主键
- **name**: 标签名称，唯一约束
- **category**: 标签类别（如：场景、服装、行为等）
- **description**: 标签描述

**索引**: 
- `idx_tags_name` (唯一索引，用于快速查找标签)
- `idx_tags_category` (用于按类别查询标签)

### 3.6 javdb_tags表

**功能**: 存储从JAVDB网站获取的特定标签。

**表结构**: 
```sql
CREATE TABLE javdb_tags (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL UNIQUE,
    url TEXT
);
```

**字段说明**: 
- **id**: 标签唯一标识符，自增主键
- **name**: 标签名称，唯一约束
- **url**: 标签对应的JAVDB页面URL

**索引**: 
- `idx_javdb_tags_name` (唯一索引，用于快速查找标签)

### 3.7 javdb_info_tags表

**功能**: javdb_info和javdb_tags之间的多对多关联表。

**表结构**: 
```sql
CREATE TABLE javdb_info_tags (
    javdb_info_id INTEGER,
    javdb_tag_id INTEGER,
    PRIMARY KEY (javdb_info_id, javdb_tag_id),
    FOREIGN KEY (javdb_info_id) REFERENCES javdb_info (id) ON DELETE CASCADE,
    FOREIGN KEY (javdb_tag_id) REFERENCES javdb_tags (id) ON DELETE CASCADE
);
```

**字段说明**: 
- **javdb_info_id**: JAVDB信息ID，外键关联javdb_info表
- **javdb_tag_id**: JAVDB标签ID，外键关联javdb_tags表
- **复合主键**: 确保一个标签在同一个视频中只出现一次

**关系特性**: 
- 配置了级联删除，当JAVDB信息或标签被删除时，关联记录也会自动删除

### 3.8 folders表

**功能**: 存储视频文件所在的文件夹信息。

**表结构**: 
```sql
CREATE TABLE folders (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    folder_path TEXT NOT NULL UNIQUE,
    name TEXT NOT NULL,
    date_added TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**字段说明**: 
- **id**: 文件夹唯一标识符，自增主键
- **folder_path**: 文件夹的完整路径，唯一约束
- **name**: 文件夹名称
- **date_added**: 文件夹添加到数据库的时间戳

**索引**: 
- `idx_folders_folder_path` (唯一索引，用于快速查找文件夹)

## 5. 数据库索引优化

为了提高查询性能，数据库设计中包含了多个索引。以下是索引的详细说明和优化建议：

### 5.1 现有索引

- **videos表**: `idx_videos_file_path` (唯一), `idx_videos_md5_hash`, `idx_videos_folder_id`
- **actors表**: `idx_actors_name` (唯一)
- **javdb_info表**: `idx_javdb_info_video_id` (唯一)
- **tags表**: `idx_tags_name` (唯一), `idx_tags_category`
- **javdb_tags表**: `idx_javdb_tags_name` (唯一)
- **folders表**: `idx_folders_folder_path` (唯一)

### 5.2 推荐添加的索引

1. **对于频繁的日期查询**:
   ```sql
   CREATE INDEX idx_videos_date_added ON videos(date_added);
   CREATE INDEX idx_javdb_info_release_date ON javdb_info(release_date);
   ```

2. **对于按文件大小范围查询**:
   ```sql
   CREATE INDEX idx_videos_file_size ON videos(file_size);
   ```

3. **对于评分查询**:
   ```sql
   CREATE INDEX idx_javdb_info_score ON javdb_info(score);
   ```

## 6. 常用查询示例

### 6.1 查询视频及其关联的演员

```sql
SELECT v.file_name, a.name
FROM videos v
JOIN video_actors va ON v.id = va.video_id
JOIN actors a ON va.actor_id = a.id
WHERE v.folder_id = ?;
```

### 6.2 查询具有特定标签的视频

```sql
SELECT v.file_name, j.title
FROM videos v
JOIN javdb_info j ON v.id = j.video_id
JOIN javdb_info_tags jt ON j.id = jt.javdb_info_id
JOIN javdb_tags t ON jt.javdb_tag_id = t.id
WHERE t.name = ?;
```

### 6.3 查找重复的视频文件（基于MD5）

```sql
SELECT md5_hash, COUNT(*) as count
FROM videos
WHERE md5_hash IS NOT NULL AND md5_hash != ''
GROUP BY md5_hash
HAVING COUNT(*) > 1;
```

### 6.4 统计各文件夹中的视频数量

```sql
SELECT f.name, COUNT(v.id) as video_count
FROM folders f
LEFT JOIN videos v ON f.id = v.folder_id
GROUP BY f.id
ORDER BY video_count DESC;
```

### 6.5 查询评分最高的10个视频

```sql
SELECT v.file_name, j.title, j.score
FROM videos v
JOIN javdb_info j ON v.id = j.video_id
WHERE j.score IS NOT NULL
ORDER BY j.score DESC
LIMIT 10;
```

## 7. 数据库维护与优化建议

### 7.1 定期备份

- 建议定期使用系统提供的备份功能备份数据库文件
- 备份文件存储在`db_backups/`目录下
- 可以使用脚本自动化备份过程

### 7.2 性能优化

- **定期重建索引**: 长时间使用后，索引可能会碎片化，影响查询性能
- **VACUUM操作**: 执行VACUUM命令可以回收未使用的空间并优化数据库文件
- **避免大事务**: 尽量将大事务拆分为多个小事务，提高并发性能

### 7.3 数据完整性

- **使用外键约束**: 系统已配置外键约束，确保数据之间的引用完整性
- **事务处理**: 对涉及多个表的操作使用事务，确保原子性
- **定期检查完整性**: 使用工具脚本定期检查数据库完整性

### 7.4 安全建议

- **访问控制**: 限制对数据库文件的访问权限
- **密码保护**: SQLite支持数据库加密，可以考虑为敏感数据添加密码保护
- **防止SQL注入**: 使用参数化查询，避免直接拼接SQL语句

## 8. 数据库扩展说明

系统设计考虑了未来的扩展性，以下是一些可能的扩展方向：

### 8.1 表结构扩展

- **添加新字段**: 可以根据需要向现有表添加新字段
- **创建新表**: 可以创建新表来存储额外的元数据或分析结果

### 8.2 数据类型优化

- **使用适当的数据类型**: 为字段选择合适的数据类型，优化存储空间和查询性能
- **文本压缩**: 对于大文本字段，可以考虑使用压缩存储

### 8.3 高级功能

- **全文搜索**: 可以启用SQLite的全文搜索扩展，提高文本搜索性能
- **空间索引**: 如果需要地理位置相关的功能，可以添加空间索引
- **触发器**: 可以使用触发器自动维护派生数据或执行验证

## 9. 总结

媒体库管理系统的数据库设计遵循了规范化原则，建立了清晰的数据结构和关系。通过合理的索引设计和约束配置，确保了数据的完整性和查询性能。数据库支持系统的所有核心功能，包括视频管理、元数据存储、演员和标签关联等。定期的维护和优化可以确保数据库的长期稳定运行和良好性能。
