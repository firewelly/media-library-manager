# PySide 迁移实施任务清单

- 文档版本: v1
- 适用范围: `media_library_pyside.py` 及其配套适配/扩展模块
- 目标读者: 负责并行实施的开发 agent、人类维护者、回归验证 agent
- 文档性质: 执行任务拆解，不是设计文档；实现时以当前代码为准

## 1. 背景

当前仓库中已经存在一套可运行的 Tk 主界面实现 `media_library.py`，以及一套 PySide 版本实现 `media_library_pyside.py`。  
PySide 版本已经具备基础浏览、搜索、部分批量工具和部分维护功能，但仍存在以下几类迁移缺口：

1. 某些菜单入口“表面存在、实际未接通”，仍会落到 `original_*` 占位逻辑。
2. 单文件右键菜单、多选右键菜单与 Tk 版本相比仍有明显能力缺口。
3. 详情区信息密度和可编辑能力弱于 Tk 版本。
4. 扩展补丁与扩展对话框仍存在加载路径、占位实现和功能未收口问题。
5. 若继续无计划地追加功能，会让 PySide 版本出现更多“有入口、没闭环”的技术债。

注意：

1. `doc/pyside_missing_features.md` 和 `doc/pyside_menu_comparison.md` 含有历史信息，可作为参考，但不能视为最终真相。
2. 迁移工作的事实依据应优先来自当前代码：
   - `media_library.py`
   - `media_library_pyside.py`
   - `gui_adapter.py`
   - `extension_dialogs.py`
   - `obs/pyside_extensions_patch.py`

## 2. 总目标

将 PySide 界面从“可用但不完整的替代界面”提升为“能够覆盖 Tk 主流程的主力桌面界面”，满足以下结果：

1. 核心高频功能在 PySide 中具备明确入口、可执行逻辑和完整反馈。
2. Tk 版高频整理能力在 PySide 中达到同等可用级别。
3. 所有已暴露给用户的 PySide UI 入口都具备明确行为，不允许继续保留“正在集成中”“开发中”的半成品入口。
4. 扩展模块与主界面之间的边界清晰，避免重复入口、重复实现和无效补丁加载。
5. 回归验证覆盖单文件操作、多文件操作、详情编辑、批量任务、菜单入口、异常路径。

## 3. 本阶段不做的内容

以下内容不属于本轮 `task.md` 的默认必做项，除非用户单独批准：

1. 不重写整个 PySide 架构。
2. 不强行把 Tk 的每个内部实现一比一搬到 Qt；允许复用后端逻辑、重做 UI 表现。
3. 不处理纯视觉美化类问题，除非它影响功能可达性或可理解性。
4. 不优先迁移低频脚本工具，只处理主界面可见、用户高频路径涉及的能力。
5. 不处理与本轮迁移无关的 Tk 列宽问题、数据库 schema 重构、爬虫策略大改。

## 4. 迁移成功标准

### 4.1 功能标准

1. 菜单项无“假入口”。
2. 单文件右键菜单覆盖 Tk 版本高频整理动作。
3. 多选右键菜单覆盖 Tk 版本高频批量动作。
4. 详情区支持 Tk 主界面中最常用的关键信息查看与编辑。
5. 扩展模块可稳定加载或被正式下线，不允许处于“存在但默认无效”的状态。

### 4.2 工程标准

1. 所有新入口必须绑定真实实现，不得仅弹提示框。
2. 变更尽量收敛在 PySide 相关文件，不影响 Tk 主版本行为。
3. 每个任务都必须有可验证的验收标准。
4. 完成后至少具备最小自动化回归，或给出明确人工验证步骤。

## 5. 当前问题基线

以下问题应作为本轮迁移的输入基线。

### 5.1 P0 问题

1. `media_library_pyside.py` 中存在重复定义的菜单处理方法，后定义版本会回退到 `original_*` 占位分支，导致：
   - `on_comprehensive_media_update`
   - `on_import_videos`
   - `on_sync_stars_to_filename`
   - `on_smart_remove_duplicates`
   - `on_file_move_manager`
   这类入口在部分路径下并未真正落到可执行实现。
2. `media_library_pyside.py` 默认尝试直接导入 `pyside_extensions_patch`，但当前补丁文件实际位于 `obs/pyside_extensions_patch.py`，存在默认加载失败风险。
3. `extension_dialogs.py` 中 `NFODialog`、`DuplicateManagerDialog` 仍存在明显 TODO。

### 5.2 P1 问题

1. 单文件右键菜单缺少 Tk 版高频操作：
   - `JAVDB信息获取`
   - `更新元数据`
   - `导入NFO`
   - `迁移JavSP到...`
   - `复制JavSP到...`
2. 多选右键菜单缺少 Tk 版批量操作：
   - `批量自动标签`
   - `批量JAVDB信息获取`
   - `批量更新元数据`
   - `批量生成封面`

### 5.3 P2 问题

1. 详情区缺少 Tk 版关键信息块：
   - 年份
   - 类型
   - JAVDB标签
   - 发行商
   - 磁力链接/复制入口
2. `save_video_info()` 仅保存标题、描述、标签，不能覆盖 Tk 版的编辑能力。
3. 左侧日志控件存在“UI 已有但行为未接线”的问题。

## 6. 实施原则

1. 先修“入口失效”，再补“功能缺口”，最后补“体验细节”。
2. 先保证主路径闭环，不优先做边角功能。
3. 优先复用已有后端逻辑，不新造第二套业务实现。
4. 每个 agent 只改自己负责的工作流边界，避免多人同时改 `MainWindow` 同一块区域。
5. 每一阶段结束必须补充“做了什么、验证了什么、剩什么”。

## T0. 建立迁移基线

### 目标

把“当前代码哪些地方已实现、哪些地方是假入口、哪些是历史文档误差”整理清楚，避免后续 agent 重复踩坑。

### 子任务

1. 输出当前 PySide 功能清单。
2. 标记“已实现但未接线”的函数。
3. 标记“UI 有入口但仅弹提示框”的函数。
4. 标记“历史文档与当前代码不一致”的部分。

### 交付物

1. 一份基线表格，可直接贴回本 `task.md` 或单独放在 `doc/` 下。

### 验收标准

1. 每个菜单入口、右键入口、详情区按钮，都能回答“是否真实可用”。

### 依赖

无。

## T1. 修复主菜单假入口

### 优先级

P0

### 目标

确保主菜单中的下列入口全部具备真实行为，不再依赖 `original_*` 占位：

1. 智能媒体库更新
2. 导入视频文件
3. 同步打分到文件
4. 智能去重
5. 文件移动管理

### 子任务

1. 清查 `media_library_pyside.py` 中重复定义的方法，明确后定义覆盖前定义的情况。
2. 确定这些入口应：
   - 直接调用 PySide 已有实现
   - 通过 `gui_adapter.py` 适配 Tk 逻辑
   - 或由 `AdvancedToolsManager` / `MaintenanceManager` 承担
3. 删除或重构 `original_*` 回退分支。
4. 保证菜单点击后：
   - 有实际执行逻辑
   - 有成功/失败反馈
   - 能刷新界面状态

### 涉及文件

1. `media_library_pyside.py`
2. `gui_adapter.py`

### 验收标准

1. 点击上述 5 个菜单项不再弹“正在集成中”。
2. 每项都能进入稳定逻辑或明确报错。
3. 无重复定义覆盖导致的行为不确定问题。

### 风险

1. 若直接删除后定义方法，可能影响已接入的信号槽。
2. 若复用 Tk 方法，要确认 Qt 对话框适配路径完整。

## T2. 修复扩展补丁加载路径与策略

### 优先级

P0

### 目标

让扩展模块要么稳定生效，要么明确下线，不能处于默认导入失败但静默忽略的状态。

### 子任务

1. 统一 `pyside_extensions_patch` 的真实导入路径。

4. 若不保留扩展补丁：
   - 把有效能力并回主界面

### 涉及文件

1. `media_library_pyside.py`
2. `obs/pyside_extensions_patch.py`

### 验收标准

1. 启动 PySide 时扩展加载路径明确、行为可预测。

## 9. 推荐执行顺序

必须按以下顺序推进：

1. `T0` 建立基线
2. `T1` 修复菜单假入口
3. `T2` 修复扩展补丁加载策略
4. `T3` 补单文件右键
5. `T4` 补多选右键
6. `T5` 补详情区
7. `T6` 清理扩展对话框 TODO
8. `T7` 清理辅助 UI 未接线问题
9. `T8` 补测试与验收清单

原因：

1. 如果先补右键和详情，不先解决假入口和补丁加载，会让代码入口更加混乱。
2. 如果不先统一扩展策略，后续 agent 会同时改主界面和补丁文件，冲突概率很高。

## 12. Definition of Done
